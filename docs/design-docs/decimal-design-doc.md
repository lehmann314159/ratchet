# decimal — Design Document

## Overview

`decimal` is a Go library for **exact base-10 fixed-point arithmetic** — the kind
a money or invoicing system needs, where `0.1 + 0.2` must be exactly `0.3` and
rounding rules are specified rather than inherited from IEEE-754. A value is an
`int64` coefficient and a non-negative decimal `Scale`: the number it represents
is `Coef × 10^(-Scale)`. The library parses decimal literals, formats them back
to canonical text, and provides add / subtract / multiply / divide / round /
compare. A small CLI (`main.go`) reads one operation per line from stdin and
prints one result line each, so the whole library is exercisable end to end
without a network or a REPL.

Consumers: application code that needs precise decimal math (billing, tax,
unit prices). Runtime model: **library** plus a thin **CLI** harness. There is
no server, no persistence, no `math/big`.

**Domain parameters — all explicit, do not infer:**

- **Coefficient type is `int64`, usable range `[-9223372036854775807,
  9223372036854775807]` — symmetric about zero.** `math.MinInt64`
  (`-9223372036854775808`) is **not** a permitted coefficient: any operation
  that would produce it (including a `Parse` of `"-9223372036854775808"`)
  returns `ErrOverflow`, so it is never stored. This keeps `Neg`, `Abs`, and
  `String` total (they can assume the magnitude negates without overflow). Every
  operation that would produce a coefficient (or an intermediate) outside the
  usable range returns `ErrOverflow`. Overflow is **never** a panic and
  **never** silently wraps — every comparison and scaling step is written so it
  cannot overflow an `int64` before the check (see Behavioral Specification).
- **`Scale` is `int32` and always `>= 0`.** There is no negative scale (no
  "scale = -2 means hundreds"). `Round` and `Div` reject a negative target scale.
- **Value equality vs. text form.** `1.5` and `1.50` are *equal in value*
  (`Cmp` returns 0) but are *different `Decimal` values* (`Scale` 1 vs 2) and
  format differently (`"1.5"` vs `"1.50"`). No operation normalises away trailing
  zeros.
- **Parse grammar** (see Behavioral Specification for the exact rule): optional
  single leading `+` or `-`, then digits, optionally `.` and **at least one**
  digit. `.5` is valid (0.5). `5.` is **invalid**. No exponent (`1e5`), no digit
  separators (`1,000` / `1_000`), no surrounding or internal whitespace.
- **Negative zero is never produced or printed.** A coefficient of 0 formats as
  `"0"` (or `"0.00"` at Scale 2) with no sign, regardless of how it arose
  (`-0.0` parsed, `5 - 5`, `-1 × 0`).
- **Rounding modes — exactly three, no default:**
  - `RoundHalfUp` — ties round **away from zero** (`2.5 → 3`, `-2.5 → -3`).
  - `RoundHalfEven` — ties round to the **even** neighbour (`2.5 → 2`,
    `3.5 → 4`, `-2.5 → -2`); "banker's rounding".
  - `RoundDown` — **truncate toward zero**, always, regardless of the dropped
    digits (`2.9 → 2`, `-2.9 → -2`). This is *not* floor.
- **`Div` has no implicit scale.** The caller must pass both a target `Scale`
  and a `RoundingMode`. There is no "divide exactly" path — `1/3` at scale 4 is
  `0.3333`, and `1/2` at scale 0 with `RoundHalfEven` is `0`.
- **Out of scope:** `math/big` / arbitrary precision; parsing exponent or
  currency-symbol notation; `Cmp` on operand pairs whose scale-alignment would
  overflow `int64` (both individual coefficients fit but `max`-scale rescaling
  does not — e.g. `9e18` vs `0.1`); locale-aware formatting; JSON marshalling.

## Architecture

```
decimal/
├── decimal.go   — type Decimal, type RoundingMode + constants, the sentinel
│                   errors, and the three value-only methods Neg / Abs / IsZero
├── parse.go     — Parse
├── format.go    — (Decimal).String
├── arith.go     — Add, Sub, Cmp  (and the unexported align helper)
├── mul.go       — Mul
├── round.go     — Round  (and the unexported applyRounding helper)
├── div.go       — Div
├── main.go      — func main, plus run(line) and parseMode(s) — the CLI
└── *_test.go    — one test file per source file above, plus integration_test.go
```

All `.go` files use `package main` at the project root — one flat package, no
subdirectories. Module name is `decimal`. `go.mod` and `do_not_use_this_test.go`
are generated by scaffolding — do not list them as outputs.

**File assignment rules (strict):**

- `decimal.go` contains: `type Decimal`, `type RoundingMode` and its three
  constants, `var ErrSyntax / ErrOverflow / ErrDivideByZero / ErrNegativeScale`,
  and the methods `(Decimal).Neg`, `(Decimal).Abs`, `(Decimal).IsZero`. Nothing
  else. It declares **no** arithmetic.
- `parse.go` contains exactly `Parse`. `format.go` contains exactly
  `(Decimal).String`.
- `arith.go` contains `Add`, `Sub`, `Cmp`, and the unexported `align`. No
  multiplication, no division, no rounding.
- `mul.go` contains exactly `Mul`. `div.go` contains exactly `Div`.
- `round.go` contains `Round` and the unexported `applyRounding`.
- `main.go` contains `func main()`, `func run(line string) string`, and
  `func parseMode(s string) (RoundingMode, error)` — nothing else.
- Do **not** put `Add`/`Sub` in `decimal.go`. Do **not** put `align` in
  `decimal.go` — it lives with its only callers in `arith.go`. Do **not** put
  `applyRounding` in `div.go` — `div.go` *calls* it from `round.go` (see the
  Cross-Bead Contract). Do **not** put `Mul` or `Div` logic in `arith.go`.

## Data Types and Function Signatures

All `.go` source files use `package main`. Module name is `decimal`. Requires
Go 1.22.

```go
// ---- decimal.go ----

// Decimal is a base-10 fixed-point number. The value it represents is
// Coef * 10^(-Scale). Scale is always >= 0.
type Decimal struct {
	Coef  int64
	Scale int32
}

type RoundingMode int

const (
	RoundHalfUp   RoundingMode = iota // ties away from zero
	RoundHalfEven                      // ties to the even neighbour
	RoundDown                          // truncate toward zero
)

var (
	ErrSyntax        = errors.New("decimal: invalid syntax")
	ErrOverflow      = errors.New("decimal: int64 overflow")
	ErrDivideByZero  = errors.New("decimal: divide by zero")
	ErrNegativeScale = errors.New("decimal: scale must be >= 0")
)

func (d Decimal) Neg() Decimal
func (d Decimal) Abs() Decimal
func (d Decimal) IsZero() bool

// ---- parse.go ----

func Parse(s string) (Decimal, error)

// ---- format.go ----

func (d Decimal) String() string

// ---- arith.go ----

func Add(a, b Decimal) (Decimal, error)
func Sub(a, b Decimal) (Decimal, error)
func Cmp(a, b Decimal) int

// align rescales a and b to a common scale = max(a.Scale, b.Scale) and returns
// the two rescaled coefficients plus that scale. err is ErrOverflow if either
// rescale leaves int64 range.
func align(a, b Decimal) (ca int64, cb int64, scale int32, err error)

// ---- mul.go ----

func Mul(a, b Decimal) (Decimal, error)

// ---- round.go ----

func Round(d Decimal, scale int32, mode RoundingMode) (Decimal, error)

// applyRounding adjusts a truncated quotient q, given the dropped remainder rem
// out of divisor div (0 <= rem < div, both non-negative), returning the rounded
// quotient. See the Behavioral Specification for the exact rule per mode.
func applyRounding(q int64, rem int64, div int64, mode RoundingMode) int64

// ---- div.go ----

func Div(a, b Decimal, scale int32, mode RoundingMode) (Decimal, error)

// ---- main.go ----

func main()
func run(line string) string
func parseMode(s string) (RoundingMode, error)
```

## Behavioral Specification

### `decimal.go` — `Neg`, `Abs`, `IsZero`

Pure value methods, no error path. They are total because no other operation
ever stores `math.MinInt64` in `Coef` (Domain parameters) — so `-d.Coef` and
`|d.Coef|` always fit `int64`.

- **`(Decimal).Neg`** — returns `{Coef: -d.Coef, Scale: d.Scale}`. `Neg` of a
  zero coefficient is still a zero coefficient (there is no negative zero to
  create).
- **`(Decimal).Abs`** — returns `d` with a non-negative coefficient, `Scale`
  unchanged.
- **`(Decimal).IsZero`** — `d.Coef == 0`, irrespective of `Scale`. `{0, 0}` and
  `{0, 5}` are both zero.

### `parse.go` — `Parse`

`Parse` converts a decimal literal to a `Decimal`. It is the *only* entry point
that produces a `Decimal` from text.

**The grammar, exactly** — read as a left-to-right scan, not a regexp to
re-derive:

1. If the string is empty → `ErrSyntax`.
2. Consume an optional single sign character: `+` or `-`. A `-` sets the result
   negative. After consuming the sign, if nothing remains → `ErrSyntax`.
3. Split the remainder on the first `.` into `intPart` and `fracPart`.
   - If there is **no** `.`: `fracPart` is empty, `intPart` is the whole
     remainder.
   - If there **is** a `.`: `fracPart` must be **non-empty** — a trailing `.`
     with no fractional digit (`"5."`) is `ErrSyntax`. A second `.` anywhere
     (`"1.2.3"`) is `ErrSyntax`.
4. `intPart` may be empty (`".5"` → `intPart` `""`, `fracPart` `"5"`). Both parts
   empty (which happens only for input `"."` or sign + `"."`) → `ErrSyntax`.
5. Let `digits = intPart + fracPart`. If `digits` is empty → `ErrSyntax`. Every
   byte of `digits` must be `'0'`–`'9'`; any other byte → `ErrSyntax`. (This is
   what rejects `"1,000"`, `"1_000"`, `"1e5"`, `" 1"`, `"1 "`.)
6. Accumulate `digits` into an `int64` coefficient, most-significant digit first
   (`coef = coef*10 + digit`). The magnitude limit is `math.MaxInt64`
   **regardless of sign** — check *before* each step (`coef > (MaxInt64 -
   digit) / 10`), never let `coef` overflow then look. So
   `"9223372036854775808"` and `"-9223372036854775808"` **both** →
   `ErrOverflow` (not `ErrSyntax`): `math.MinInt64` is not a permitted
   coefficient even though it would fit `int64` (Domain parameters).
7. Apply the sign. `Scale` is `len(fracPart)` — the fractional-digit count **as
   written**, so `"1.50"` has `Scale` 2 and `"7"` has `Scale` 0. Leading zeros in
   `intPart` do not affect `Scale` (`"007.50"` → `{750, 2}`).

`Parse` never trims whitespace and never accepts an exponent.

### `format.go` — `(Decimal).String`

The inverse of `Parse` for every value `Parse` can produce (see the round-trip
Cross-Bead Contract). Canonical rules:

1. Take the magnitude of `Coef` as a base-10 digit string with no leading zeros
   (`0` for a zero coefficient).
2. If `Scale == 0`: the body is that digit string, with **no** trailing `.`.
3. If `Scale > 0`: left-pad the digit string with zeros until it has at least
   `Scale + 1` digits, then insert a `.` so exactly `Scale` digits are to its
   right. So `{5, 2}` → digits `"5"` → pad to `"005"` → `"0.05"`; `{150, 2}` →
   `"1.50"`; `{0, 3}` → `"0.000"`.
4. Prepend `"-"` **only if** `Coef < 0` **and** the magnitude is non-zero. A zero
   coefficient never gets a sign — `{0, 2}` is `"0.00"`, never `"-0.00"`.

### `arith.go` — `Add`, `Sub`, `Cmp`

All three go through `align` first.

- **`align(a, b)`** — `scale = max(a.Scale, b.Scale)`. Rescale each coefficient
  by `10^(scale - that operand's scale)`. Both the power itself and the
  multiplication are computed by repeated `× 10` with an `int64`-range check
  **before each step**; any step that would leave range → `ErrOverflow`. Never
  materialise `10^k` as an `int64` and check only the following multiply.
  Returns `(a.Coef * 10^…, b.Coef * 10^…, scale, nil)`.
- **`Add(a, b)`** — `align`, then add the two rescaled coefficients. If the
  integer addition would produce a value outside the usable range
  `[-MaxInt64, MaxInt64]` → `ErrOverflow` (this includes a result of exactly
  `math.MinInt64`). Result `Scale` is the
  aligned `scale` = `max(a.Scale, b.Scale)`: `Add({15,1}, {150,2})` → `{300+150
  = ... }` wait — `{15,1}` rescales to `{150,2}`, plus `{150,2}` → `{300, 2}` =
  `"3.00"`, **not** `"3.0"`.
- **`Sub(a, b)`** — defined as `Add(a, b.Neg())`. Same scale rule:
  `Sub({10,2}, {1,1})` → `Sub` rescales `{1,1}`→`{10,2}` → `{0, 2}` = `"0.00"`.
- **`Cmp(a, b)`** — `align`, then return `-1`, `0`, `+1` as the rescaled
  `a` coefficient is `<`, `==`, `>` the rescaled `b` coefficient. Value
  comparison: `Cmp({15,1}, {150,2})` = `0`. `Cmp` returns an `int`, not an
  error; operand pairs whose alignment overflows are out of scope (Overview).

### `mul.go` — `Mul`

- **`Mul(a, b)`** — `Coef = a.Coef * b.Coef` (if this leaves the usable range
  `[-MaxInt64, MaxInt64]`, checked without letting the product wrap first →
  `ErrOverflow`), `Scale = a.Scale + b.Scale`. Scales **add**, they are not
  aligned: `Mul({15,1}, {15,1})` → `{225, 2}` = `"2.25"`.
  `Mul({-200,2}, {3000,3})` → `{-600000, 5}` = `"-6.00000"`.
  `Mul({0,0}, {500,2})` → `{0, 2}` = `"0.00"`.

### `round.go` — `Round`, `applyRounding`

- **`Round(d, scale, mode)`**:
  - If `scale < 0` → `ErrNegativeScale`.
  - If `scale >= d.Scale`: no digits are dropped. Return `d` rescaled *up* —
    `Coef * 10^(scale - d.Scale)`, `Scale = scale`. The power and the multiply
    use the same step-wise `× 10` + pre-check as `align`; any step out of range
    → `ErrOverflow`. `Round({15,1}, 3, …)` → `{15000, 3}` = `"1.500"`.
  - Otherwise `drop = d.Scale - scale` digits come off. If `drop >= 19` then
    `10^drop > math.MaxInt64`, so `|d.Coef| / 10^drop == 0` and `rem == |d.Coef|`
    for any in-range coefficient — compute `q' = applyRounding(0, mag, div, mode)`
    where `div` conceptually exceeds `mag` (so `applyRounding` only ever compares
    `mag` against `div - mag`, which stays in range — see below); result
    `{ sign * q', scale }`. Otherwise `div = 10^drop` (computed step-wise),
    `mag = |d.Coef|`, `q = mag / div`, `rem = mag % div`,
    `q' = applyRounding(q, rem, div, mode)`; result `{ sign * q', scale }`.
- **`applyRounding(q, rem, div, mode)`** — `q`, `rem`, `div` are all
  non-negative and `0 <= rem < div`. The tie comparisons are written as
  `rem` vs `div - rem` (**not** `rem*2` vs `div`) because `rem*2` overflows
  `int64` when `div` is near `math.MaxInt64`, which `Div` can produce:
  - If `rem == 0` → return `q` (exact, nothing to decide).
  - `RoundDown` → return `q`. **Always.** The remainder is irrelevant. This is
    the case a "round" implementation most often gets wrong by folding it into a
    `rem > div - rem` branch — do not.
  - `RoundHalfUp` → return `q + 1` if `rem >= div - rem`, else `q`.
  - `RoundHalfEven` → return `q + 1` if `rem > div - rem`, **or** if
    `rem == div - rem` **and** `q` is odd; else `q`.

  The sign is reattached by `Round` *after* `applyRounding` — rounding always
  operates on the magnitude, so `RoundHalfUp` of `-2.5` is `-(round 2.5 up)` =
  `-3` (away from zero), and `RoundDown` of `-2.9` is `-(trunc 2.9)` = `-2`.

### `div.go` — `Div`

- **`Div(a, b, scale, mode)`**:
  - `scale < 0` → `ErrNegativeScale`. `b.IsZero()` → `ErrDivideByZero`.
  - Result sign is negative iff exactly one of `a.Coef`, `b.Coef` is negative.
    Work with magnitudes `|a.Coef|`, `|b.Coef|` from here.
  - `a / b = (|a.Coef| * 10^b.Scale) / (|b.Coef| * 10^a.Scale)`. To get `scale`
    fractional digits, scale the numerator by a further `10^scale`:
    - `num = |a.Coef| * 10^(b.Scale + scale)`
    - `den = |b.Coef| * 10^(a.Scale)`
    - Form each with the step-wise `× 10` + pre-check used by `align`; any step
      out of `int64` range → `ErrOverflow`. (This is why `Div(10, 3, 20, …)`
      overflows: `10 * 10^20` does not fit.)
  - `q = applyRounding(num / den, num % den, den, mode)` — the **same** helper
    `Round` uses (Cross-Bead Contract). Because `den` can be near
    `math.MaxInt64` here, `applyRounding`'s `rem` vs `div - rem` form (not
    `rem*2`) is load-bearing, not cosmetic. Result is `{ sign * q, scale }`.
  - Worked: `Div(1, 3, 4, RoundHalfEven)` → `num = 1*10^4 = 10000`, `den = 3`,
    `10000/3 = 3333` rem `1`, `2*1 < 3` → `q = 3333` → `{3333, 4}` = `"0.3333"`.
    `Div(2, 3, 5, RoundDown)` → `200000/3 = 66666` rem `2` → RoundDown keeps →
    `"0.66666"` (**not** `"0.66667"`).

### `main.go` — the CLI

`main` reads stdin line by line with `bufio.Scanner`. For each line: trim ASCII
whitespace; skip it if empty or if it starts with `#`; otherwise print
`run(line)` followed by `\n`. `run` returns the result string for one command.

`parseMode` maps `"half-up"` → `RoundHalfUp`, `"half-even"` → `RoundHalfEven`,
`"down"` → `RoundDown`, anything else → an error.

`run` splits the line on ASCII whitespace into fields and dispatches on
`fields[0]` (see the CLI Cross-Bead Contract for the exact command grammar and
output format).

## Cross-Bead Contracts

### format -> parse (format — round-trip)

- **type**: format
- **producer**: `format`
- **consumer**: `parse`
- **interface**: the canonical decimal string grammar from Behavioral
  Specification → `parse.go` and `format.go`. For **every** `Decimal` value `d`
  reachable from `Parse` (coefficient in `int64`, `Scale >= 0`):
  `p, err := Parse(d.String())` returns `err == nil`, `p.Scale == d.Scale`, and
  `Cmp(p, d) == 0`. And for every string `s` that `Parse` accepts:
  `Parse(s).String()` is the *canonical* form of `s` (sign normalised —
  leading `+` dropped, `-0` → `0`; leading integer zeros dropped; fractional
  digits preserved exactly).
- **notes**: `String` must not emit anything `Parse` rejects — no leading `+`,
  no `-0`, no `5.` trailing dot, no exponent. The integration bead owns the
  round-trip assertion.

### round → div (protocol — shared rounding rule)

- **type**: protocol
- **producer**: `round`
- **consumer**: `div`
- **interface**: `applyRounding(q int64, rem int64, div int64, mode RoundingMode) int64`
  — with `q, rem, div >= 0` and `0 <= rem < div`. Returns: `q` if `rem == 0`;
  `q` if `mode == RoundDown`; `q+1` if `mode == RoundHalfUp` and
  `rem >= div - rem`; `q+1` if `mode == RoundHalfEven` and (`rem > div - rem`
  **or** (`rem == div - rem` **and** `q` is odd)); otherwise `q`. (`div - rem`,
  never `rem*2` — `rem*2` overflows `int64` for a large `Div` divisor.)
- **notes**: `Div` calls this exact function from `round.go` — it does **not**
  re-implement the tie logic. A `Div` result and the corresponding
  `Round(exactQuotientAtScale+guard, scale, mode)` must agree for every input.
  `div.go` imports nothing from `round.go` except this helper.

### cli → operations (protocol — command dispatch)

- **type**: protocol
- **producer**: `cli`
- **consumer**: `parse`, `format`, `arith`, `mul`, `round`, `div`
- **interface**: `run(line string) string`. The line is split on ASCII
  whitespace into fields. Commands (field count is exact; wrong count →
  `"error: usage: <command> <args…>"` — see notes):

  | command | fields | action | output |
  |---|---|---|---|
  | `parse <s>` | 2 | `Parse(s)` | `d.String()` or `"error: " + err` |
  | `string <s>` | 2 | `Parse(s)` then re-emit | same as `parse` |
  | `add <a> <b>` | 3 | `Parse` both, `Add` | `d.String()` or `"error: " + err` |
  | `sub <a> <b>` | 3 | `Sub` | same |
  | `mul <a> <b>` | 3 | `Mul` | same |
  | `cmp <a> <b>` | 3 | `Cmp` | `"-1"`, `"0"`, or `"1"` |
  | `round <a> <scale> <mode>` | 4 | `Round(Parse(a), scale, mode)` | `d.String()` or `"error: " + err` |
  | `div <a> <b> <scale> <mode>` | 5 | `Div` | same |

- **notes**: `run` validates in **left-to-right field order** and returns the
  first failure — `fields[1]`, then `fields[2]`, then (for `round`/`div`)
  `<scale>`, then `<mode>`. So `round abc -1 bogus` → `"error: decimal: invalid
  syntax"` (the `abc` operand). A `Parse` failure on an operand →
  `"error: " + err.Error()` (the two possible strings are
  `"error: decimal: invalid syntax"` and `"error: decimal: int64 overflow"`).
  `<scale>` that is not a non-negative integer → `"error: scale must be a
  non-negative integer"`. `<mode>` not in `half-up` / `half-even` / `down` →
  `"error: unknown rounding mode \"<mode>\""`. Wrong field count for a known
  command → `"error: usage: <command> <args…>"` (e.g. `"error: usage: add <a>
  <b>"`). Unknown command → `"error: unknown command <field0>"`. Every error
  line begins with the literal `"error: "`.

## Decomposition Notes

**Bead dependency order (do not reorder):**

1. **types** — `Decimal`, `RoundingMode` + the three constants, the four sentinel
   errors, `Neg`, `Abs`, `IsZero`. No dependencies. Owns `decimal.go`.
2. **parse** — `Parse`. Depends on bead 1. Owns `parse.go`.
3. **format** — `(Decimal).String`. Depends on bead 1. Owns `format.go`.
4. **arith** — `Add`, `Sub`, `Cmp`, and the unexported `align`. Depends on
   bead 1. Owns `arith.go`.
5. **mul** — `Mul`. Depends on bead 1. Owns `mul.go`.
6. **round** — `Round`, and the unexported `applyRounding`. Depends on bead 1.
   Owns `round.go`.
7. **div** — `Div`. Depends on beads 1 and 6. Owns `div.go`.
8. **cli** — `main`, `run`, `parseMode`. Depends on beads 1, 2, 3, 4, 5, 6, 7
   (bead 1 for `RoundingMode`, which `parseMode` returns). Owns `main.go`.
   sizing rationale: `main.go` is one stdin loop plus one command switch in
   `run`; no shared assembly logic, each case is an independent
   two-or-three-line call into a library function already covered by its own bead.
9. **integration** — the format↔parse round-trip plus one fixed CLI script.
   Depends on beads 2, 3, 4, 8 (bead 4 for `Cmp`, used in the round-trip check).

**Integration bead scenario (bounded):** build `[]Decimal{ {12345,2}, {-1,3},
{0,0}, {70,1}, {5,2}, {600000,5} }`; for each, assert
`Parse(d.String())` returns nil error, equal `Scale`, and `Cmp == 0`. Then feed
this exact 6-line script to `run` (one call per line) and assert the exact output
lines (each line below is `<command fed to run>` then `->` then `<expected
result>`; only the command text is fed):

```
add 0.10 0.20        -> 0.30
sub 1.00 0.1         -> 0.90
mul 1.5 1.5          -> 2.25
div 1 3 4 half-even  -> 0.3333
round -2.5 0 half-up -> -3
cmp 2 2.0            -> 0
```

- **Pin — `parse` bead, grammar edge cases (verbatim, must be followed exactly,
  not re-derived):** `".5"` → `{Coef: 5, Scale: 1}`; `"5."` → `ErrSyntax`; `"."`
  → `ErrSyntax`; `""` → `ErrSyntax`; `"1.2.3"` → `ErrSyntax`; `"1,000"` →
  `ErrSyntax`; `"1e5"` → `ErrSyntax`; `" 1"` → `ErrSyntax`; `"+7.0"` →
  `{Coef: 70, Scale: 1}`; `"007.50"` → `{Coef: 750, Scale: 2}`;
  `"9223372036854775808"` **and** `"-9223372036854775808"` → `ErrOverflow` (not
  `ErrSyntax`; `math.MinInt64` is not a permitted coefficient). `Scale` is the
  count of digits written after `.`.
- **Pin — `format` bead, canonical form (verbatim):** `{0,0}` → `"0"`;
  `{0,3}` → `"0.000"`; `{5,2}` → `"0.05"`; `{150,2}` → `"1.50"`; `{-1,3}` →
  `"-0.001"`; `{-5,0}` → `"-5"`; a zero coefficient is **never** printed with a
  `-` sign, at any scale. No trailing `.` when `Scale == 0`.
- **Pin — `arith` bead, result scale is `max(a.Scale, b.Scale)` (verbatim):**
  `Add({15,1}, {150,2})` → `{300, 2}` = `"3.00"` (NOT `"3.0"`);
  `Sub({10,2}, {1,1})` → `{0, 2}` = `"0.00"`; `Cmp({15,1}, {150,2})` → `0`
  (equal by value); `Add({9223372036854775807,0}, {1,0})` → `ErrOverflow`;
  `Add({-9223372036854775807,0}, {-1,0})` → `ErrOverflow` (a result of exactly
  `math.MinInt64` overflows — the usable range is symmetric).
- **Pin — `mul` bead, scales add (verbatim):** `Mul({15,1}, {15,1})` →
  `{225, 2}` = `"2.25"`; `Mul({1,1}, {1,1})` → `{1, 2}` = `"0.01"`;
  `Mul({-200,2}, {3000,3})` → `"-6.00000"` (Scale 5);
  `Mul({0,0}, {500,2})` → `"0.00"`.
- **Pin — `round` bead, mode behaviour on ties and negatives (verbatim, must be
  followed exactly, not re-derived or paraphrased):** rounding operates on the
  magnitude; the sign is reattached afterward.
  - `RoundHalfUp` ties away from zero: `2.5`→`"3"`, `-2.5`→`"-3"`, `2.45` at
    scale 1 → `"2.5"`.
  - `RoundHalfEven` ties to even: `2.5`→`"2"`, `3.5`→`"4"`, `-2.5`→`"-2"`,
    `-1.5`→`"-2"`, `2.45` at scale 1 → `"2.4"`, `2.55` at scale 1 → `"2.6"`,
    `2.675` at scale 2 → `"2.68"`, `9.95` at scale 1 → `"10.0"`.
  - `RoundDown` truncates toward zero **always**, ignoring the dropped digits:
    `2.9`→`"2"`, `-2.9`→`"-2"`. Do NOT implement `RoundDown` as a
    `rem > div - rem` branch. Tie comparisons everywhere use `rem` vs
    `div - rem`, never `rem*2` (which overflows for a large `Div` divisor).
  - `scale >= d.Scale` raises the scale with zero padding: `1.5` at scale 3 →
    `"1.500"`. Negative scale → `ErrNegativeScale`.
- **Pin — `div` bead, quotient scale + rounding + errors (verbatim):**
  `Div(1,3, scale 4, half-even)` → `"0.3333"`; `Div(2,3, scale 5, down)` →
  `"0.66666"` (truncated, NOT `"0.66667"`); `Div(-7,2, scale 0, down)` → `"-3"`;
  `Div(-7,2, scale 0, half-up)` → `"-4"`; `Div(7,2, scale 0, half-even)` →
  `"4"`; `Div(5,2, scale 0, half-even)` → `"2"`; `Div(1,7, scale 10, half-even)`
  → `"0.1428571429"`; `Div(x, 0, …)` → `ErrDivideByZero`;
  `Div(10,3, scale 20, half-even)` → `ErrOverflow`. `Div` rounds by calling the
  `round` bead's `applyRounding` helper, not its own copy of the tie rule.
- **Pin — `cli` / `integration` beads, output format (verbatim):** one result
  line per command; the result of a value-returning command is `d.String()`;
  `cmp` prints `"-1"`, `"0"`, or `"1"`; any failure prints `"error: " +
  err.Error()` and every error line begins with the literal `"error: "`. Blank
  lines and lines beginning with `#` are skipped, not echoed.
