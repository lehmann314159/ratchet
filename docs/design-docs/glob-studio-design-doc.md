# Glob Studio — Design Document

## Overview

Glob Studio is a single-page Go web app for exploring glob patterns. The user
types a glob pattern and a list of candidate paths (one per line); the app shows,
for each path, whether it matches, plus a plain-English breakdown of the pattern
and its `/`-separated segment structure. A handful of preset (pattern, paths)
examples can be loaded into the form with one click.

Runtime model: a single HTTP server, one flat `package main`, no database, no
persistence, no external services. **Out of scope:** brace expansion `{a,b}`,
extended-glob operators (`?(...)`, `+(...)`, `@(...)`, `!(...)`), tilde
expansion, case-insensitive matching, matching against a real filesystem,
Windows path separators, authentication, and any client-side JavaScript beyond a
plain HTML form POST.

**Domain parameters:**

- Module name is `globstudio`. Go 1.22.
- HTTP: the server listens on `:8080` in `main` only; **every test uses
  `net/http/httptest`**, never a fixed port.
- Templates are inline Go string literals in `InitTemplates()` — there is no
  `templates/` directory and no external `.html` files.
- Paths and patterns are treated as UTF-8 strings and compared by Unicode code
  point. All worked examples in this document use ASCII.
- The path separator is `/` only. A pattern segment is a maximal run of the
  pattern between `/` characters (or between start/end and a `/`).
- Matching is **anchored**: a pattern matches a path only if it matches the
  entire path, start to end.
- There is no limit on pattern length or path count; the UI does not paginate.
- A path may be the empty string; a paths list may be empty.

### Glob syntax

| Construct | Meaning |
|---|---|
| any character except `\`, `?`, `*`, `[`, `/` | matches itself literally |
| `?` | exactly one character that is not `/` |
| `*` | any run, including empty, of characters that are not `/` |
| `**` | any run, including empty, of any characters **including** `/` — **only** when the `**` is a whole segment (bounded by `/` or by the start/end of the pattern). A `**` used as a whole segment adjacent to a `/` absorbs that `/`: `a/**/b` matches `a/b`, `a/x/b`, and `a/x/y/b`. |
| a run of two or more `*` that is **not** a whole segment | collapses to a single `*` (e.g. `a**b` behaves as `a*b`) |
| `[...]` | one character that is not `/`, drawn from the set inside the brackets |
| `[a-z]` | a range inside a class: any character whose code point is between the two endpoints inclusive |
| `[!...]` or `[^...]` | negated class: one character that is not `/` and is **not** in the set |
| `\x` | the next character `x`, treated literally (so `\*` matches a literal `*`) |

Character-class details:

- A `]` immediately after `[`, `[!`, or `[^` is a literal `]` member, not the
  closing bracket: `[]a]` matches `]` or `a`.
- A `-` that is the first or last member of a class (not part of a range) is a
  literal `-`: `[a-]` matches `a` or `-`.
- An empty class — `[]`, `[!]`, or `[^]` (no members after the optional negation
  mark) — is a **pattern error** (`"empty character class"`, reported by
  `Parse`; `Lex` accepts these as an empty-body `TokClass`).
- A reversed range (`[z-a]`, high endpoint before low) is a **pattern error**
  (`"reversed range"`). `[c-a-z]` is scanned greedily left-to-right, so `c-a` is
  the first range → reversed-range error.
- An unterminated class (`[` with no closing `]`) is a **pattern error**
  (`"unterminated character class"`, reported by `Lex`).
- A negated class never matches `/`, the same as a positive class.

Pattern errors:

- Unterminated character class.
- Empty character class.
- Reversed range in a character class.
- A trailing `\` with no following character.

A pattern error is reported to the user as an error message; it is **not** an
HTTP error.

**File assignment rules (strict):**

- `main.go` contains exactly `var templates *template.Template` and `func main()`.
  No types, no handlers, no constants.
- `lexer.go` contains `Token`, `TokenKind` and its constants, and `Lex`. It does
  **not** validate character-class bodies (that is `parser.go`) and knows
  nothing about matching.
- `parser.go` contains `Node`, `Elem`, and `Parse`. It **uses** `Token` /
  `TokenKind` from `lexer.go` (same package, no import). It does **not** call
  `Lex`, and it does no matching.
- `matcher_classes.go` contains exactly `classToRegex` — a string→string helper
  that translates one character-class body (the raw `Elem.Text` for a `TokClass`,
  leading `!`/`^` preserved) into a Go `regexp` bracket expression. No other
  functions, no types. It does **not** import `regexp`, call `Lex` / `Parse`, or
  touch `Node` / `Elem`.
- `matcher.go` contains `Program`, `Compile`, and `Match`. It **uses** `Node` /
  `Elem` from `parser.go` and calls `classToRegex` from `matcher_classes.go`
  (same package, no import). It does **not** call `Lex` or `Parse` and does not
  build English text.
- `explain.go` contains `Explain`. It **uses** `Node` / `Elem`. No matching, no
  lexing.
- `segments.go` contains `Segments`. It **uses** `Node` / `Elem`. No matching,
  no lexing.
- `studio.go` contains `MatchRow`, `Result`, and `Evaluate`. `Evaluate` calls
  `Lex`, `Parse`, `Compile`, `Match`, `Explain`, and `Segments` in that order.
  It defines no glob logic of its own.
- `presets.go` contains `Preset` and `var Presets []Preset`. No functions other
  than the slice literal.
- `templates.go` contains `InitTemplates` and `RenderPage`. No handler
  functions, no type declarations, no glob logic.
- `handlers.go` contains `PageView`, `assemble`, `HandleIndex`, `HandleMatch`,
  `HandleSelect`. No template parsing, no re-implementation of `Evaluate`.
- Do **not** put `Lex` in `parser.go`, `Parse` in `matcher.go`, or `Compile` /
  `Match` in `studio.go`.
- Do **not** put `classToRegex` in `matcher.go` — it belongs in
  `matcher_classes.go`. Do **not** inline the character-class translation into
  `Compile`; `Compile` calls `classToRegex`.
- Do **not** put `Node` / `Elem` in `lexer.go` — they belong in `parser.go`.
- Do **not** put `PageView` in `templates.go` — it belongs in `handlers.go`.
- Do **not** put any `Handle*` function in `templates.go` or `studio.go`.
- Do **not** put `var templates` anywhere except `main.go`.

## Data Types and Function Signatures

```go
// ---- lexer.go ----

type TokenKind int

const (
    TokLiteral    TokenKind = iota // Text is a run of literal characters
    TokAny                         // ?
    TokStar                        // * (non-slash run)
    TokDoubleStar                  // ** as a whole segment
    TokClass                      // Text is the raw class body, without the outer [ ],
                                   // with a leading '!' or '^' kept if the class is negated
    TokSep                        // /
)

type Token struct {
    Kind TokenKind
    Text string // meaningful for TokLiteral and TokClass; "" otherwise
}

// Lex scans a glob pattern into a flat token list.
//   - A run of literal characters (including any produced by a \x escape) becomes
//     one TokLiteral; adjacent literal runs are merged.
//   - '?' -> TokAny; '/' -> TokSep.
//   - A run of one '*' -> TokStar. A run of two or more '*' that forms a whole
//     segment (bounded by '/' or the start/end of the pattern) -> TokDoubleStar;
//     otherwise the whole run -> a single TokStar.
//   - '[' begins a class: Lex skips a leading '!' or '^', then skips a single
//     leading ']' ONLY if another character precedes the next ']' (so '[]a]' has
//     body ']a', but '[]', '[!]', '[^]' are classes with an empty body). It
//     scans to the closing ']' and emits one TokClass whose Text is the body.
//     Lex does NOT check the body for validity (Parse rejects an empty body).
//   - '\' escapes the next character, which is emitted as a literal. A '\' with no
//     following character is an error.
// Errors (exact strings): "dangling backslash"; "unterminated character class".
func Lex(pattern string) ([]Token, error)

// ---- parser.go ----

// Elem is one element of a parsed pattern. Kind reuses the lexer's kinds. For
// TokLiteral, Text is the literal run; for TokClass, Text is the raw body
// (leading '!' or '^' preserved). For all other kinds Text is "".
type Elem struct {
    Kind TokenKind
    Text string
}

// Node is a parsed pattern: a flat, ordered list of elements. There is no
// nesting in a glob.
type Node struct {
    Elems []Elem
}

// Parse converts a token list into a Node and validates every character class
// by a left-to-right member scan (see Behavioral Specification): the class body
// must have at least one member after the optional negation mark, and every
// "a-b" range must have a code point for a that is <= the code point for b.
// Adjacent TokLiteral tokens are merged. Parse does no lexing and no matching.
// Errors (exact strings): "empty character class"; "reversed range".
func Parse(tokens []Token) (Node, error)

// ---- matcher_classes.go ----

// classToRegex translates one character-class body into a Go regexp bracket
// expression. body is the raw Elem.Text for a TokClass: the characters between
// the outer [ ], with a leading '!' or '^' kept if the class is negated.
//   - A leading '!' or '^' means negated.
//   - A negated class is emitted as "[^/" + rest + "]" — it excludes '/' as well
//     as its members.
//   - A positive class is emitted as "[" + body + "]" (a positive class is not
//     expected to contain '/').
//   - A ']' that is the first body character (after an optional negation mark)
//     is a literal member and must be emitted as "\]" so Go's regexp accepts it.
//   - A trailing '-' is left as-is (Go treats it as a literal).
// classToRegex assumes Parse already accepted the class (non-empty, ranges not
// reversed); it does not re-validate.
func classToRegex(body string) string

// ---- matcher.go ----

// Program is a compiled matcher. Its internal representation is unspecified; it
// is produced only by Compile and consumed only by Match.
type Program struct {
    // unexported fields
}

// Compile turns a parsed Node into a Program by translating node.Elems into a
// single anchored Go regexp (\A ... \z) per the table in Behavioral
// Specification -> Compile, calling classToRegex for every TokClass. Compile
// never fails on a Node that Parse returned (Parse has already rejected the
// invalid cases).
func Compile(node Node) *Program

// Match reports whether the whole of path matches the whole of the pattern that
// prog was compiled from (anchored on both ends). See "Behavioral Specification"
// and "Domain-Specific Test Scenarios" for the exact semantics of *, **, ?, and
// character classes with respect to '/'.
func Match(prog *Program, path string) bool

// ---- explain.go ----

// Explain returns one human-readable line per element of node, in order. The
// exact strings are pinned in Domain-Specific Test Scenarios.
func Explain(node Node) []string

// ---- segments.go ----

// Segments returns the pattern's '/'-separated segments, each re-rendered from
// the parsed elements in canonical form (a run of '*' shown as "*", a
// whole-segment "**", "?" as "?", a class as "[" + body + "]", literals as
// their text). The number of returned segments is one more than the number of
// TokSep elements in node.
func Segments(node Node) []string

// ---- studio.go ----

type MatchRow struct {
    Path    string
    Matched bool
}

type Result struct {
    Pattern     string
    Explanation []string   // Explain(node)
    Segments    []string   // Segments(node)
    Rows        []MatchRow // one per input path, in the given order
}

// Evaluate runs the whole pipeline: Lex(pattern) -> Parse -> Compile, then
// Match(prog, p) for each p in paths, and Explain / Segments on the parsed node.
// On any Lex or Parse error it returns (Result{}, err) with err.Error() a
// human-readable message. On success it returns (Result{...}, nil).
func Evaluate(pattern string, paths []string) (Result, error)

// ---- presets.go ----

type Preset struct {
    Name    string   // stable id used by POST /select
    Label   string   // shown on the button
    Pattern string
    Paths   []string
}

var Presets []Preset

// ---- templates.go ----

// InitTemplates parses the inline template strings and returns the set. It
// panics on a parse error (template text is a compile-time constant).
func InitTemplates() *template.Template

// RenderPage renders the full page (form + optional result) from v. Every
// handler renders via RenderPage — this is a plain form-POST app with no
// fragment swaps, so every response is a full page.
func RenderPage(w http.ResponseWriter, v PageView)

// ---- handlers.go ----

type PageView struct {
    Pattern    string   // current pattern in the form
    Paths      string   // current textarea content, newline-separated
    Presets    []Preset // always Presets
    Result     *Result  // nil until a match has run
    ParseError string   // non-empty when the last Evaluate failed
}

// assemble builds a PageView. rawPaths is the exact textarea content. result is
// nil unless a match has just run; parseErr is "" unless it failed.
func assemble(pattern, rawPaths string, result *Result, parseErr string) PageView

func HandleIndex(w http.ResponseWriter, r *http.Request)  // GET /
func HandleMatch(w http.ResponseWriter, r *http.Request)  // POST /match
func HandleSelect(w http.ResponseWriter, r *http.Request) // POST /select

// ---- main.go ----

var templates *template.Template
```

## Behavioral Specification

### `Lex(pattern string) ([]Token, error)`

Single left-to-right scan. `\` consumes the next character and contributes it to
the current literal run (so `\a` and `a` lex identically; `\*` becomes a literal
`*`). `[` starts a class scan: skip an optional leading `!` or `^`, then skip a
single leading `]` **only if at least one more character precedes the next `]`**
(so `[]a]` has body `]a` and `[]]` has body `]`, but `[]`, `[!]`, and `[^]` are
recognized as classes with an **empty body** — `Token.Text` is `""`, `"!"`, or
`"^"` — and `Lex` does **not** error on them); then scan to the next `]`. If the
end of the pattern is reached before a closing `]` → return the exact error
string `"unterminated character class"` from `Lex`. An empty-body class is
`Lex`-valid and reaches `Parse`, which rejects it (`"empty character class"`).
The class body emitted in `Token.Text` keeps the leading `!` or `^` but not the
brackets. A run of `*` is
counted; it becomes `TokDoubleStar` only if its length is >= 2 **and** the
character before the run is `/` or the start of the pattern **and** the
character after the run is `/` or the end of the pattern; otherwise the entire
run is one `TokStar`.

### `Parse(tokens []Token) (Node, error)`

Copies tokens into `Node.Elems`, merging consecutive `TokLiteral`. For each
`TokClass`, parse the body into members by a **left-to-right scan**: consume a
leading `!`/`^` as the negation mark. Then, at each position: if the current
character is followed by `-` **and** that `-` is followed by a character (i.e.
the `-` is not the last body character), consume all three as a range `low-high`;
otherwise the current character is a single-character member. A `-` in the first
member position, in the last member position, or immediately after a completed
range is a literal `-` member. Under this scan `[c-a-z]` parses `c-a` as the
first range. Reject an **empty class** (no members after the negation mark →
`"empty character class"`) and any **range whose low endpoint's code point
exceeds its high endpoint's** (`"reversed range"`). Parse builds no matcher.

### `classToRegex(body string) string`

`body` is the raw class body for a `TokClass` `Elem` — the text between the outer
`[ ]`, with a leading `!` or `^` kept if the class is negated. `Parse` has
already accepted it (non-empty, no reversed range); `classToRegex` does not
re-validate.

1. If `body` begins with `!` or `^`, the class is **negated**; drop that first
   byte and call the remainder `rest`. Otherwise the class is **positive** and
   `rest` is `body` unchanged.
2. If `rest` begins with `]`, replace that leading `]` with `\]` (Go's `regexp`
   does not treat a leading `]` in a class as a literal, unlike a shell glob).
3. Negated → return `"[^/" + rest + "]"`. The `/` makes a negated class exclude
   the path separator as well as its listed members.
4. Positive → return `"[" + rest + "]"`. (A positive class is not expected to
   contain `/`.)

Worked: `classToRegex("a-c")` = `"[a-c]"`; `classToRegex("!a-c")` = `"[^/a-c]"`;
`classToRegex("]abc")` = `"[\]abc]"`; `classToRegex("a-")` = `"[a-]"`.

### `Compile` and `Match`

`Compile` is a pure transform and never fails on a `Node` from `Parse`. It walks
`node.Elems` in order, emits one regexp fragment per element per the table
below, concatenates them, wraps the result as `` `\A` + body + `\z` ``, and
compiles it with `regexp.MustCompile` (the anchors make `Match` whole-string).
`Match` returns `prog`'s compiled regexp `.MatchString(path)`.

Per-element fragments:

| element | fragment |
|---|---|
| `TokLiteral` | `regexp.QuoteMeta(Elem.Text)` |
| `TokAny` (`?`) | `[^/]` |
| `TokStar` (`*`) | `[^/]*` |
| `TokClass` | `classToRegex(Elem.Text)` |
| `TokSep` (`/`) | `/` — **except** when the next element is `TokDoubleStar` (see below) |
| `TokDoubleStar` (`**`) | depends on adjacent `TokSep` — see below |

`TokDoubleStar` is, by construction (the lexer only emits it as a whole
segment), always adjacent to a `TokSep` on at least one side, or is the entire
pattern. **First collapse any maximal run of `TokDoubleStar` elements separated
by single `TokSep`s** (`** / **`, `** / ** / **`, …) into **one** `TokDoubleStar`
— a chain of "any depth" is still "any depth". Then translate each remaining
`**` **together with** its adjacent `TokSep`(s) as one unit, and do not
separately emit those `TokSep`(s):

| context | element run | fragment |
|---|---|---|
| whole pattern | `**` | `.*` |
| start of pattern | `**` `/` | `(?:.*/)?` |
| end of pattern | `/` `**` | `(?:/.*)?` |
| interior | `/` `**` `/` | `/(?:.*/)?` |

Worked regexps (these must be exact): `*.go` → `` `\A[^/]*\.go\z` ``;
`**/*.go` → `` `\A(?:.*/)?[^/]*\.go\z` ``; `src/**` → `` `\Asrc(?:/.*)?\z` ``;
`src/**/test` → `` `\Asrc/(?:.*/)?test\z` ``; `**` → `` `\A.*\z` ``;
`**/**` → `` `\A.*\z` `` (the chain collapses to a single whole-pattern `**`);
`a/**/**/b` → `` `\Aa/(?:.*/)?b\z` `` (chain collapses to one interior `**`);
`[!a-c]at` → `` `\A[^/a-c]at\z` ``.

Net semantics this produces, relative to `/`: `?` / `*` / a character class each
consume exactly the bytes their fragment allows and never `/`; `TokSep` consumes
one `/`; `**` consumes zero or more bytes including `/` and absorbs one adjacent
`/` (so `a/**/b` matches `a/b`, `a/x/b`, `a/x/y/b`; `**/x` matches `x`; `a/**`
matches `a`; a lone `**` matches any path including the empty string).

### `Explain(node Node) []string`

One line per element, in order. Exact output strings pinned in Domain-Specific
Test Scenarios.

### `Segments(node Node) []string`

Walk `node.Elems`, accumulating a canonical rendering of each element into the
current segment string; on each `TokSep`, push the current segment and start a
new one; push the final segment at the end. `len(result)` is always
`(number of TokSep elements) + 1`.

### `Evaluate(pattern string, paths []string) (Result, error)`

`Lex` then `Parse`; if either returns an error, return `(Result{}, err)` — do
not partially populate `Result`. Otherwise `Compile` once, then one
`Match(prog, p)` per `p` in `paths` (order preserved, duplicates kept), and
`Explain` / `Segments` on the parsed node. `Result.Pattern` is the input
pattern verbatim.

### Handlers

All three handlers produce their response by calling `RenderPage(w, v)` with a
fully-populated `PageView` — there is no fragment-only response.

`HandleIndex` (`GET /`): `RenderPage` with an empty form and the preset
buttons. `PageView.Result` is nil, `ParseError` is "".

`HandleMatch` (`POST /match`): read form fields `pattern` and `paths`. Split
`paths` on `"\n"` and, for each line, trim a single trailing `"\r"` (so a
CRLF-submitted textarea works) but do not trim other whitespace; drop lines that
are empty after that trim. Call `Evaluate(pattern, lines)`. On success:
`RenderPage` with `PageView.Result` set. On error: `RenderPage` with
`PageView.ParseError` set to `err.Error()` and `Result` nil. **Always HTTP
200** — a bad pattern is user input, not an HTTP error.

`HandleSelect` (`POST /select`): read form field `preset`. If it names a
`Presets` entry, `RenderPage` with that preset's `Pattern` and its `Paths`
joined by `"\n"` pre-filled in the form, `Result` nil. If it names no entry,
`RenderPage` with the empty form (HTTP 200).

**Form-body encoding.** `r.ParseForm()` / `r.PostForm.Get` decode
`application/x-www-form-urlencoded`, where `+` decodes to a space and `%NN` is a
byte. Every `httptest` request body in a test **must** be built with
`url.Values{...}.Encode()`. A hand-written body with a raw `+`, `&`, `;`, `%`,
or space in the `pattern` or `paths` value — all of which occur in real glob
input — is decoded wrongly and the assertion then fails for the wrong reason.
Do **not** hand-roll a `+`-preserving form parser.

**Rendered-HTML assertions.** `html/template` escapes by output context.
A pattern like `[a-c]*` rendered inside the value attribute or inside a
`<td>` appears in the response bytes with `<`, `>`, `&`, `"` escaped
(`&lt;` `&gt;` `&amp;` `&#34;`), and inside a `<textarea>` the same. Test
assertions on the response body must use substrings that contain **no**
HTML-special characters — assert on `class="match"`, on a path string with no
metacharacters (`main.go`), or on an `Explain` line's plain-text portion, never
on a raw `<` or `&` or a `"`-delimited attribute fragment.

### `main()`

Build `templates = InitTemplates()`, populate the mux — `GET /` -> `HandleIndex`,
`POST /match` -> `HandleMatch`, `POST /select` -> `HandleSelect` — and
`http.ListenAndServe(":8080", mux)`.

## Domain-Specific Test Scenarios

### Coordinate system

Paths are byte strings. Position 0 is the first byte. The only structural
character is `/`. `*`, `?`, and character classes never cross a `/`; `**` (as a
whole segment) does. "Anchored" means the match must begin at position 0 and end
at the last byte.

### Required test scenarios for the `matcher-classes` bead (`classToRegex`)

Each row: `classToRegex(body)` returns exactly the stated string.

| `body` | result |
|---|---|
| `a-c` | `[a-c]` |
| `!a-c` | `[^/a-c]` |
| `^a-c` | `[^/a-c]` |
| `0-9` | `[0-9]` |
| `!0-9` | `[^/0-9]` |
| `]abc` | `[\]abc]` |
| `!]abc` | `[^/\]abc]` |
| `a-` | `[a-]` |
| `abc` | `[abc]` |

### Required test scenarios for the `matcher` bead (`Compile` + `Match`)

Each row: compile the pattern, then `Match` against the path, expecting the
stated boolean. (Character-class translation is the `matcher-classes` bead's
concern; these rows exercise `Compile`/`Match` end to end and assume
`classToRegex` is correct.)

| pattern | path | `Match` |
|---|---|---|
| `*.go` | `main.go` | **true** |
| `*.go` | `src/main.go` | **false** — `*` does not cross `/` |
| `*.go` | `.go` | **true** — `*` matches the empty run |
| `*.go` | `main.gox` | **false** — anchored at the end |
| `src/*.go` | `src/main.go` | **true** |
| `src/*.go` | `src/a/b.go` | **false** |
| `**/*.go` | `main.go` | **true** — leading `**/` consumes nothing |
| `**/*.go` | `src/main.go` | **true** |
| `**/*.go` | `src/a/main.go` | **true** |

## Cross-Bead Contracts

### lexer → parser (data-shape)

- **type**: data-shape
- **producer**: lexer
- **consumer**: parser
- **interface**: `type Token struct { Kind TokenKind; Text string }` where
  `TokenKind` is one of `TokLiteral, TokAny, TokStar, TokDoubleStar, TokClass,
  TokSep`. `Text` is non-empty only for `TokLiteral` (a literal run) and
  `TokClass` (the class body without brackets, leading `!`/`^` kept).
- **notes**: `Parse` must accept the token slice as-is; consecutive
  `TokLiteral` may appear and `Parse` merges them.

### parser → matcher (data-shape)

- **type**: data-shape
- **producer**: parser
- **consumer**: matcher
- **interface**: `type Elem struct { Kind TokenKind; Text string }` and
  `type Node struct { Elems []Elem }`. For `TokClass`, `Elem.Text` is the raw
  body (leading `!`/`^` preserved). `Node` is flat and ordered.
- **notes**: `Compile` may assume every `Elem` is well-formed — `Parse` has
  already rejected empty classes and reversed ranges. `Compile` passes
  `Elem.Text` for a `TokClass` straight to `classToRegex`.

### matcher-classes → matcher (protocol)

- **type**: protocol
- **producer**: matcher-classes
- **consumer**: matcher
- **interface**: `func classToRegex(body string) string` — `body` is the raw
  `TokClass` `Elem.Text` (leading `!`/`^` preserved); the return value is a Go
  `regexp` bracket expression, negated forms already excluding `/`.
- **notes**: `Compile` emits `classToRegex(Elem.Text)` verbatim as the fragment
  for every `TokClass` element and does not post-process it.

### parser → explain (data-shape)

- **type**: data-shape
- **producer**: parser
- **consumer**: explain
- **interface**: `type Elem struct { Kind TokenKind; Text string }`,
  `type Node struct { Elems []Elem }` (as above).
- **notes**: `Explain` reads `Node.Elems` in order and emits one line each; it
  does not re-parse `Elem.Text`.

### parser → segments (data-shape)

- **type**: data-shape
- **producer**: parser
- **consumer**: segments
- **interface**: `type Elem struct { Kind TokenKind; Text string }`,
  `type Node struct { Elems []Elem }` (as above).
- **notes**: `Segments` splits on `TokSep` elements; the result length is the
  `TokSep` count plus one.

### matcher → studio (protocol)

- **type**: protocol
- **producer**: matcher
- **consumer**: studio
- **interface**: `func Compile(node Node) *Program` and
  `func Match(prog *Program, path string) bool`.
- **notes**: `Evaluate` calls `Compile` exactly once and `Match` once per input
  path, preserving order and duplicates.

### explain → studio (protocol)

- **type**: protocol
- **producer**: explain
- **consumer**: studio
- **interface**: `func Explain(node Node) []string`.
- **notes**: `Evaluate` stores the result in `Result.Explanation` unchanged.

### segments → studio (protocol)

- **type**: protocol
- **producer**: segments
- **consumer**: studio
- **interface**: `func Segments(node Node) []string`.
- **notes**: `Evaluate` stores the result in `Result.Segments` unchanged.

### studio → handlers (data-shape)

- **type**: data-shape
- **producer**: studio
- **consumer**: handlers
- **interface**: `type MatchRow struct { Path string; Matched bool }` and
  `type Result struct { Pattern string; Explanation []string; Segments []string; Rows []MatchRow }`.
- **notes**: On a pattern error `Evaluate` returns `(Result{}, err)`; the
  handler puts `err.Error()` into `PageView.ParseError` and leaves
  `PageView.Result` nil. On success the handler sets `PageView.Result` to the
  address of the returned `Result`.

### presets → handlers (data-shape)

- **type**: data-shape
- **producer**: presets
- **consumer**: handlers
- **interface**: `type Preset struct { Name string; Label string; Pattern string; Paths []string }` and `var Presets []Preset`.
- **notes**: `HandleSelect` matches its `preset` form field against `Preset.Name`.
  `assemble` always copies `Presets` into `PageView.Presets`.

### handlers → templates (data-shape)

- **type**: data-shape
- **producer**: handlers
- **consumer**: templates
- **interface**: `type PageView struct { Pattern string; Paths string; Presets []Preset; Result *Result; ParseError string }`.
- **notes**: Inside a `{{range .Presets}}` loop the template must use `$.` to
  reach page-level fields if needed. `{{if .Result}}` gates the result block;
  `{{if .ParseError}}` gates the error line. All of `Pattern`, `Paths`, every
  `MatchRow.Path`, and every `Explanation` line render through `html/template`
  and are escaped by context — see Behavioral Specification → Handlers →
  Rendered-HTML assertions. **Load-bearing exact strings the templates bead must
  emit** (the integration bead asserts on them): the page's outermost element
  has `id="app"`; each result row carries `class="match"` when its
  `MatchRow.Matched` is true and `class="nomatch"` when false — those exact
  class names, not synonyms.

## Decomposition Notes

**Bead dependency order (do not reorder):**

1. **lexer** — `Token`, `TokenKind` + constants, `Lex`. No dependencies. Owns
   `lexer.go`.
2. **parser** — `Elem`, `Node`, `Parse`. Depends on bead 1. Owns `parser.go`.
3. **matcher-classes** — `classToRegex`. Depends on bead 2 (for the `Elem.Text`
   class-body shape only; it takes a `string`, not a `Node`). Owns
   `matcher_classes.go`.
4. **matcher** — `Program`, `Compile`, `Match`. Depends on beads 2 and 3.
   `Compile` is a table-driven translation of `Node.Elems` to one anchored Go
   regexp (see Behavioral Specification → `Compile`), calling `classToRegex` for
   each `TokClass`. Owns `matcher.go`.
5. **explain** — `Explain`. Depends on bead 2. Owns `explain.go`.
6. **segments** — `Segments`. Depends on bead 2. Owns `segments.go`.
7. **studio** — `MatchRow`, `Result`, `Evaluate`. Depends on beads 1, 2, 4, 5,
   6. Owns `studio.go`.
8. **presets** — `Preset`, `Presets`. No dependencies. Owns `presets.go`.
9. **templates** — `InitTemplates`, `RenderPage`. Decompose **before** handlers
   so the handler bead's httptest assertions run against real rendered HTML.
   Owns `templates.go`.
10. **handlers** — `PageView`, `assemble`, `HandleIndex`, `HandleMatch`,
    `HandleSelect`. Depends on beads 7, 8, 9. Owns `handlers.go`.

    functions are thin parse-request / call-`Evaluate` / render wrappers with no
    shared logic beyond `assemble`.
11. **main** — `var templates`, `func main()`. Wires the mux. Depends on bead 10.
    Owns `main.go`.
12. **integration** — one bounded `httptest` scenario (below).

**Pins (verbatim worked values — carry into the named bead's spec exactly, do
not re-derive or paraphrase):**

- **Pin — `matcher` bead, `Match` semantics vs `/`:** `*.go` matches `main.go`
  but **not** `src/main.go` (`*` never crosses `/`); `*.go` matches `.go` (empty
  run). `**/*.go` matches all of `main.go`, `src/main.go`, `src/a/main.go`, and
  not `src/main.rs`. `src/**` matches `src`, `src/a`, `src/a/b`, and not
  `srcx/a` (trailing `/**` may consume nothing). `src/**/test` matches
  `src/test`, `src/a/test`, `src/a/b/test`, not `src/test/x`. `?at` does not
  match `/at`. `a**b` (not a whole segment) matches `axxb` but not `ax/xb`.
  `**` alone matches `a/b/c` and the empty string. `*` matches `abc` not `a/b`.
- **Pin — `matcher` bead, `Compile` → regexp translation (verbatim, do not
  re-derive):** per element — `TokLiteral` → `regexp.QuoteMeta(text)`; `TokAny`
  → `[^/]`; `TokStar` → `[^/]*`; `TokClass` → `classToRegex(text)`; `TokSep` →
  `/` unless the next element is `TokDoubleStar`. A `TokDoubleStar` **with its
  adjacent `TokSep`(s)** translates as one unit: whole pattern `**` → `.*`;
  start `**` `/` → `(?:.*/)?`; end `/` `**` → `(?:/.*)?`; interior `/` `**` `/`
  → `/(?:.*/)?`. **Before translating, collapse a run of `**` elements separated
  by single `/`** (`**/**`, `a/**/**/b`, …) into one `**`. Wrap the
  concatenation as `` `\A` + body + `\z` `` and `regexp.MustCompile`. Exact
  results: `*.go` → `\A[^/]*\.go\z`; `**/*.go` → `\A(?:.*/)?[^/]*\.go\z`;
  `src/**` → `\Asrc(?:/.*)?\z`; `src/**/test` → `\Asrc/(?:.*/)?test\z`; `**` →
  `\A.*\z`; `**/**` → `\A.*\z`; `a/**/**/b` → `\Aa/(?:.*/)?b\z`.
- **Pin — `matcher-classes` bead, `classToRegex` (verbatim):** `classToRegex`
  takes the raw class body (leading `!`/`^` kept). A leading `!` or `^` → the
  class is negated: drop it, and return `"[^/" + rest + "]"` (a negated class
  excludes `/` too). Otherwise return `"[" + body + "]"`. If `rest` (after any
  negation mark) begins with `]`, rewrite that leading `]` as `\]`. Exact:
  `classToRegex("a-c")` = `[a-c]`; `classToRegex("!a-c")` = `[^/a-c]`;
  `classToRegex("]abc")` = `[\]abc]`; `classToRegex("a-")` = `[a-]`.
- **Pin — `matcher` bead, end-to-end class behavior:** `[a-c]at` matches `bat`,
  not `dat`, not `Bat` (`'B'`=66 < `'a'`=97). `[!a-c]at` matches `dat`, not
  `bat`, and **never** `/at`. `[]abc]` matches `]` and `a` (leading `]` is
  literal). `[a-]` matches `a` and `-`. `\*.txt` matches the literal `*.txt`,
  not `a.txt`.
- **Pin — `parser` bead, error cases (exact error strings):** `[]`, `[!]`, `[^]`
  → `Lex` accepts them as empty-body `TokClass`; `Parse` returns exactly
  `"empty character class"`. `[z-a]` and `[c-a-z]` → `Parse` returns exactly
  `"reversed range"` (`[c-a-z]` is scanned greedily, `c-a` first). `[abc`
  (unterminated) → `Lex` returns exactly `"unterminated character class"`;
  `ab\` → `Lex` returns exactly `"dangling backslash"` — both surface before
  `Parse`. `[]a]`, `[]]`, `[a-]`, `[a-c]` parse cleanly.
- **Pin — `explain` bead, `Explain` output:** `Explain` on the parsed
  `src/**/*.go` returns exactly
  `["literal text \"src\"", "path separator", "** — any run (including empty) of any characters, crossing /", "path separator", "* — any run (including empty) of characters other than /", "literal text \".go\""]`.
  On `[!a-c]at` it returns
  `["[!a-c] — one character other than / and not in the set \"a-c\"", "literal text \"at\""]`.
- **Pin — `segments` bead, `Segments` output:** `Segments` on the parsed
  `src/**/*.go` returns `["src", "**", "*.go"]`; on `*.go` returns `["*.go"]`;
  on `**` returns `["**"]`; on `[!a-c]at` returns `["[!a-c]at"]`.
- **Pin — `studio` bead, `Evaluate`:** `Evaluate("src/*.go", []string{"src/main.go", "src/a/b.go", "main.go"})`
  returns a `Result` with `Rows` = `[{"src/main.go", true}, {"src/a/b.go", false}, {"main.go", false}]`,
  `Segments` = `["src", "*.go"]`, and `Explanation` the four-line slice for

- **Pin — `templates` bead, load-bearing exact strings:** `RenderPage` output's
