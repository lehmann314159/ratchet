# gapbuffer — Design Document

## Overview

`gapbuffer` is a Go library implementing a **gap buffer** — the text-buffer data
structure used at the core of many editors, where the storage is one contiguous
slice with a movable empty "gap" so that repeated edits near the same position
are cheap. On top of the raw buffer it provides byte access, slicing, and
line/column navigation. A CLI (`main.go`) replays an edit script line by line so
the whole structure is exercisable from stdin.

Consumers: an editor or text-processing tool that needs an efficient editable
buffer. Runtime model: **library** plus a **CLI** edit-script replayer. No
server, no files, no third-party dependency.

**Domain parameters — all explicit, do not infer:**

- **Byte-oriented.** The buffer stores and indexes **bytes**, not runes. All
  positions are 0-based byte offsets into the logical text. UTF-8 correctness is
  the caller's responsibility. A "line" is a maximal run of bytes not containing
  `\n`; the `\n` byte itself belongs to the line it terminates.
- **The gap is invisible.** `String()`, `At`, `Slice`, and every line operation
  behave as if the text were a plain `[]byte` of length `Len()`. The gap's
  position is observable **only** through `GapPosition()`, which exists so tests
  can confirm the structure is a real gap buffer (the gap moved to the last
  edit) rather than a naive slice.
- **`New(initial)`** places the gap at the **end** of `initial` (so
  `GapPosition()` == `len(initial)` immediately after `New`, or `0` for an empty
  buffer).
- **`Insert(pos, s)`** requires `0 <= pos <= Len()`; `pos == Len()` (append) is
  valid. After the call the gap sits **immediately after** the inserted text:
  `GapPosition() == pos + len(s)`. Inserting `""` is a no-op except that it
  moves the gap to `pos`.
- **`Delete(pos, n)`** requires `pos >= 0`, `n >= 0`, and `pos + n <= Len()`.
  After the call `GapPosition() == pos`. Guards run **in order**: `pos < 0` or
  `n < 0` → `ErrArg` (checked first); then `pos + n > Len()` → `ErrRange`. So
  `Delete(-1, 100)` returns `ErrArg`.
- **`At(pos)`** requires `0 <= pos < Len()` (strict upper bound — there is no
  byte at `Len()`).
- **`Slice(start, end)`** requires `0 <= start <= end <= Len()`; `start == end`
  yields `""`.
- **`LineCount()`** is `1 + (number of \n bytes)`. An empty buffer has **1**
  line. `"a\n"` has **2** lines (the second is empty).
- **`LineBounds(line)`** returns `[start, end)` **excluding** the trailing `\n`.
  For the last line, `end == Len()`. Requires `0 <= line < LineCount()`.
- **`PosToLineCol(pos)`** requires `0 <= pos <= Len()` (`Len()` is valid and
  reports the position just past the last byte). `line` = number of `\n` bytes
  before `pos`; `col` = bytes from that line's start. A `pos` that lands exactly
  on a `\n` reports that `\n`'s line and a `col` equal to that line's length.
- **`LineColToPos(line, col)`** requires `0 <= line < LineCount()` and
  `0 <= col <= (end - start)` for that line (col may equal the line length, i.e.
  point at the `\n` or at `Len()`); out of range → `ErrRange`.
- **Errors are two sentinels**: `ErrRange` (a position/index outside its allowed
  interval) and `ErrArg` (a negative count where a non-negative one is
  required). Both are returned, never panicked.

**Out of scope:** rune / grapheme awareness; undo/redo; multiple cursors or
selections; markers that track edits; `io.Reader`/`io.Writer` adapters;
concurrency (the buffer is single-goroutine); files.

## Architecture

```
gapbuffer/
├── gapbuffer.go  — type GapBuffer, New, Len, String; the two sentinel errors;
│                    the unexported gap mechanics (gapLen, moveGap, grow)
├── edit.go       — Insert, Delete, GapPosition
├── access.go     — At, Slice
├── lines.go      — LineCount, LineBounds, PosToLineCol, LineColToPos
├── main.go       — func main, run, escape, unescape, type cli  — the CLI
└── *_test.go     — one test file per source file above, plus integration_test.go
```

All `.go` files use `package main` at the project root — one flat package, no
subdirectories. Module name is `gapbuffer`. `go.mod` and
`do_not_use_this_test.go` are generated by scaffolding.

**File assignment rules (strict):**

- `gapbuffer.go` owns `type GapBuffer`, `New`, `(*GapBuffer).Len`,
  `(*GapBuffer).String`, `var ErrRange` / `var ErrArg`, and the unexported gap
  mechanics `gapLen`, `moveGap`, `grow`. **All gap manipulation lives here** —
  the other beads only call the public methods and never touch `data` /
  `gapStart` / `gapEnd`.
- `edit.go` owns exactly `(*GapBuffer).Insert`, `(*GapBuffer).Delete`,
  `(*GapBuffer).GapPosition`.
- `access.go` owns exactly `(*GapBuffer).At`, `(*GapBuffer).Slice`.
- `lines.go` owns exactly `(*GapBuffer).LineCount`, `(*GapBuffer).LineBounds`,
  `(*GapBuffer).PosToLineCol`, `(*GapBuffer).LineColToPos`. It computes over
  `b.String()`; it does not read `data` directly.
- `main.go` owns `func main()`, `run` (a method on `type cli`), `escape`,
  `unescape`.
- Do **not** put `Insert`/`Delete` in `gapbuffer.go`. Do **not** let `edit.go`,
  `access.go`, or `lines.go` reach into the `GapBuffer` struct fields — they use
  `Len()`, `String()`, and (for `access`) whatever the public API gives them.

// GapBuffer is a byte-oriented text buffer backed by a gap buffer.
type GapBuffer struct {
	// unexported: data []byte, gapStart int, gapEnd int.

	// len(data) - (gapEnd - gapStart).

// ---- access.go ----

func (b *GapBuffer) At(pos int) (byte, error)
func (b *GapBuffer) Slice(start, end int) (string, error)

// ---- lines.go ----

## Behavioral Specification

### `gapbuffer.go` — storage and the gap

- **`New(initial)`** — `data = []byte(initial)`, `gapStart = gapEnd =
  len(initial)`. The gap is empty and at the end.
- **`gapLen()`** — `gapEnd - gapStart`.
- **`Len()`** — `len(data) - gapLen()`.
- **`String()`** — `data[:gapStart]` concatenated with `data[gapEnd:]`.
- **`moveGap(pos)`** — repositions the gap so `gapStart == pos`
  (`0 <= pos <= Len()`), by moving the bytes between the old and new gap
  positions across the gap:
  - `pos < gapStart`: copy `data[pos:gapStart]` to end just before `gapEnd`;
    `gapStart -= n`, `gapEnd -= n` where `n = gapStart - pos`.
  - `pos > gapStart`: copy `data[gapEnd : gapEnd + n]` to start at `gapStart`;
    `gapStart += n`, `gapEnd += n` where `n = pos - gapStart`.
- **`grow(need)`** — if `gapLen() >= need` do nothing. Otherwise allocate a
  larger backing slice, keep the before-gap text at `[0, gapStart)`, move the
  after-gap text to the **end** of the new slice, and set `gapEnd` so the gap
  fills the space between. `gapStart` is unchanged. (The exact new capacity is
  an implementation detail; the observable requirement is that after `grow`,
  `String()` and `Len()` are unchanged and the gap holds at least `need` bytes.)
  The natural wrong implementation copies the after-gap text right after the
  before-gap text and leaves the gap — and garbage — at the tail; it corrupts
  the next insert. Move the after-gap run to the far end.

### `edit.go` — `Insert`, `Delete`, `GapPosition`

- **`Insert(pos, s)`** — check `pos < 0 || pos > Len()` **first** → `ErrRange`.
  If `s == ""` → `moveGap(pos)`, return nil. Otherwise: `grow(len(s))`,
  `moveGap(pos)`, copy `s` into `data[gapStart : gapStart+len(s)]`,
  `gapStart += len(s)`. Net effect: the text now contains `s` at `pos`, and
  `GapPosition() == pos + len(s)`.
- **`Delete(pos, n)`** — checks run **in this order**, returning on the first
  that fails: (1) `pos < 0 || n < 0` → `ErrArg` (do **not** evaluate `pos + n`);
  (2) `pos + n > Len()` → `ErrRange`. So `Delete(-1, 100)` returns `ErrArg`, not
  `ErrRange`. Then: if `n == 0` → `moveGap(pos)`, return nil. Otherwise
  `moveGap(pos)`, then `gapEnd += n` (the next `n` bytes are absorbed into the
  gap). `GapPosition() == pos`.
- **`GapPosition()`** — returns `gapStart`, i.e. the logical position where the
  most recent edit left the gap.

### `access.go` — `At`, `Slice`

- **`At(pos)`** — `pos < 0 || pos >= Len()` → `(0, ErrRange)`. Otherwise
  `b.String()[pos]`.
- **`Slice(start, end)`** — `start < 0 || end < start || end > Len()` →
  `("", ErrRange)`. Otherwise `b.String()[start:end]`. `start == end` → `""`.

### `lines.go` — line/column navigation

All four compute over `text := b.String()`.

- **`LineCount()`** — `1 + strings.Count(text, "\n")`.
- **`LineBounds(line)`** — `line < 0 || line >= LineCount()` → `ErrRange`.
  Otherwise scan from index 0 past `line` newline bytes: `start` is one past the
  `line`-th `\n` (and `0` when `line == 0`). `end` is the offset of the next
  `\n` at or after `start`, or `len(text)` if there is none. `end` excludes the
  `\n`.
- **`PosToLineCol(pos)`** — `pos < 0 || pos > Len()` → `ErrRange`. `line =
  strings.Count(text[:pos], "\n")`. `lineStart = 0` if `line == 0`, else
  `strings.LastIndexByte(text[:pos], '\n') + 1`. `col = pos - lineStart`.
- **`LineColToPos(line, col)`** — `LineBounds(line)` (propagate `ErrRange`).
  `col < 0 || col > end - start` → `ErrRange`. Otherwise `start + col`.
- `PosToLineCol` and `LineColToPos` are exact inverses for every valid `pos`:
  `LineColToPos(PosToLineCol(pos)) == pos` for `pos` in `[0, Len()]`.

### `main.go` — the CLI edit-script replayer

`main` creates `cli{b: New("")}` and reads stdin line by line, skipping blank
lines and lines whose trimmed form starts with `#`, printing `c.run(line)`
followed by `\n`.

`escape(s)` maps `\n`→`\n` (two chars), `\t`→`\t`, `\`→`\\`, others unchanged.
`unescape(s)` is its inverse (`\n`, `\t`, `\\` only; a lone `\` at end or before
any other char is kept literally).

**Line splitting.** Split `line` **once** on its first space into `<cmd>` and
`<rest>`. For `init`, the whole `<rest>` (which may be empty) is the text
argument. For `insert`, split `<rest>` **once** on its first space: the part
before is `<pos>`, everything after that single space is the text argument —
kept **byte-for-byte**, including leading and trailing spaces (so `insert 5
  hi` inserts `"  hi"`). `insert 5` with no text argument at all → `Insert(5,
"")` → `ok`. `delete`, `at`, `slice`, `linebounds`, `linecol`, `pos` take a
fixed number of whitespace-separated integer fields (no text argument).

| command | action | output |
|---|---|---|
| `init <text>` | `c.b = New(unescape(text))` | `ok` |
| `insert <pos> <text>` | `Insert(pos, unescape(text))` | `ok` / `error: <e>` |
| `delete <pos> <n>` | `Delete(pos, n)` | `ok` / `error: <e>` |
| `len` | `Len()` | integer |
| `gap` | `GapPosition()` | integer |
| `lines` | `LineCount()` | integer |
| `text` | `escape(String())` | one line |
| `at <pos>` | `At(pos)` | `escape` of the one byte, or `error: <e>` |
| `slice <start> <end>` | `Slice(start, end)` | `escape` of the result, or `error: <e>` |
| `linebounds <line>` | `LineBounds(line)` | `"<start> <end>"` or `error: <e>` |
| `linecol <pos>` | `PosToLineCol(pos)` | `"<line> <col>"` or `error: <e>` |
| `pos <line> <col>` | `LineColToPos(line, col)` | integer or `error: <e>` |

**Error lines.** `<e>` is `err.Error()` — the buffer has exactly two error
values, so the only two `error: <e>` lines are
`error: gapbuffer: position out of range` (from `ErrRange`) and
`error: gapbuffer: bad argument` (from `ErrArg`). Unknown command →
`error: unknown command <cmd>`. Wrong field count for a fixed-arity command →
`error: usage: ` plus that command's signature, e.g.
`error: usage: delete <pos> <n>`, `error: usage: slice <start> <end>` (`init`
and `insert` are variadic and never produce a usage error). A non-integer in
**any** integer field emits `error: bad argument` (`at x`, `slice a b`,
`delete 2 z`, `pos m 0` — all `error: bad argument`). Every error line begins
with `error: `.

## Domain-Specific Test Scenarios

These are the buffer states / positions a test would otherwise guess wrong
(where the gap ends up, the line/col of a position on a `\n`, the exclusive
upper bounds). Each bead asserts **these exact pairs**; the matching
Decomposition Notes pins carry them into the bead specs.

### `edit` bead — gap tracking

Starting from `New("hello world")` (Len 11, `GapPosition()` 11):

| step | call | `String()` | `GapPosition()` | `Len()` |
|---|---|---|---|---|
| 1 | `Insert(5, "XX")` | `helloXX world` | 7 | 13 |
| 2 | `Insert(0, ">>")` | `>>helloXX world` | 2 | 15 |
| 3 | `Delete(2, 5)` | `>>XX world` | 2 | 10 |
| 4 | `Insert(10, "!")` (append) | `>>XX world!` | 11 | 11 |
| 5 | `Insert(11, "")` | `>>XX world!` | 11 | 11 |
| — | `Insert(-1, "z")` | — | — | `ErrRange` |
| — | `Insert(12, "z")` | — | — | `ErrRange` |
| — | `Delete(-1, 1)` | — | — | `ErrArg` |
| — | `Delete(0, 100)` | — | — | `ErrRange` |
| — | `Delete(-1, 100)` (both guards fire) | — | — | `ErrArg` (sign check runs first) |

A white-box test may additionally drive ~1000 random `Insert`/`Delete` ops and
assert `String()` matches an independently-maintained `[]byte`, and that
`GapPosition()` stays in `[0, Len()]` — this catches a wrong `grow`.

### `access` bead

From `New("abcdef")` (Len 6):

| call | result |
|---|---|
| `At(0)` | `'a'`, nil |
| `At(5)` | `'f'`, nil |
| `At(6)` | `0`, `ErrRange` |
| `At(-1)` | `0`, `ErrRange` |
| `Slice(0, 3)` | `"abc"`, nil |
| `Slice(3, 3)` | `""`, nil |
| `Slice(0, 6)` | `"abcdef"`, nil |
| `Slice(0, 7)` | `""`, `ErrRange` |
| `Slice(4, 2)` | `""`, `ErrRange` (end < start) |

### `lines` bead

`New("line0\nline1\nline2")` (Len 17):

| call | result |
|---|---|
| `LineCount()` | `3` |
| `LineBounds(0)` | `(0, 5, nil)` |
| `LineBounds(1)` | `(6, 11, nil)` |
| `LineBounds(2)` | `(12, 17, nil)` |
| `LineBounds(3)` | `(0, 0, ErrRange)` |
| `PosToLineCol(0)` | `(0, 0, nil)` |
| `PosToLineCol(5)` | `(0, 5, nil)` (pos 5 is the first `\n`) |
| `PosToLineCol(6)` | `(1, 0, nil)` |
| `PosToLineCol(17)` | `(2, 5, nil)` (pos == Len) |
| `PosToLineCol(18)` | `(0, 0, ErrRange)` |
| `LineColToPos(1, 0)` | `(6, nil)` |
| `LineColToPos(1, 5)` | `(11, nil)` (col == line length is allowed) |
| `LineColToPos(0, 6)` | `(0, ErrRange)` (col > line 0 length 5) |

`New("")`: `LineCount()` == `1`, `LineBounds(0)` == `(0, 0, nil)`,
`PosToLineCol(0)` == `(0, 0, nil)`.
`New("x\ny\nz\n")` (Len 6): `LineCount()` == `4`, `LineBounds(3)` == `(6, 6,
nil)`, `PosToLineCol(6)` == `(3, 0, nil)`.

## Cross-Bead Contracts

### gapbuffer -> edit, access, lines (data-shape — position model)

- **type**: data-shape
- **producer**: `gapbuffer`
- **consumer**: `edit`, `access`, `lines`
- **interface**: the logical text is a byte sequence of length `Len()`.
  Positions are 0-based byte offsets. `pos == Len()` is a valid **insertion
  point** and a valid `PosToLineCol` / `LineColToPos` boundary, but **not** a
  valid `At` index or `Slice` element. `String()` returns the whole logical
  text and never reveals the gap. The consumer beads operate through `Len()` and
  `String()`; they never read `data` / `gapStart` / `gapEnd`.
- **notes**: `ErrRange` is returned for a position/index outside its interval;
  `ErrArg` only for a negative count argument (`Delete`'s `n`). After `Insert`,
  `GapPosition() == pos + len(s)`; after `Delete`, `GapPosition() == pos`; after
  `New`, `GapPosition() == len(initial)`.

### cli -> gapbuffer, edit, access, lines (protocol — command grammar)

- **type**: protocol
- **producer**: `cli`
- **consumer**: `gapbuffer`, `edit`, `access`, `lines`
- **interface**: `(*cli).run(line string) string` driving the command table in
  Behavioral Specification → `main.go`.
- **notes**: `insert <pos> <text>` and `init <text>` take the **rest of the
  line** (spaces preserved) as the text argument, then `unescape` it (`\n`,
  `\t`, `\\`). All output that could contain a control byte (`text`, `at`,
  `slice`) is `escape`d to stay on one line. Every error line begins with
  `"error: "`.

## Decomposition Notes

**Bead dependency order (do not reorder):**

1. **gapbuffer** — `type GapBuffer`, `New`, `Len`, `String`, `ErrRange`,
   `ErrArg`, and the unexported gap mechanics (`gapLen`, `moveGap`, `grow`). No
   dependencies. Owns `gapbuffer.go`.
2. **edit** — `Insert`, `Delete`, `GapPosition`. Depends on bead 1. Owns
   `edit.go`.
3. **access** — `At`, `Slice`. Depends on bead 1. Owns `access.go`.
4. **lines** — `LineCount`, `LineBounds`, `PosToLineCol`, `LineColToPos`.
   Depends on bead 1. Owns `lines.go`.
5. **cli** — `main`, `run`, `escape`, `unescape`, `type cli`. Depends on beads
   1, 2, 3, 4. Owns `main.go`. sizing rationale: `run` is one command switch
   over already-tested public methods plus `escape`/`unescape`; no shared
   assembly logic.
6. **integration** — an edit-script replay through the CLI plus one direct
   line/column round-trip check over a fixed buffer. Depends on beads 1, 2, 3,
   4, 5.

**Integration bead scenario (bounded):**

- Feed this exact script to `run` and assert the exact output lines:
  ```
  init hello world      -> ok
  insert 5 XX           -> ok
  text                  -> helloXX world
  gap                   -> 7
  insert 0 >>           -> ok
  delete 2 5            -> ok
  text                  -> >>XX world
  gap                   -> 2
  len                   -> 10
  init a\nbc\nd          -> ok
  lines                 -> 3
  linebounds 1          -> 2 4
  linecol 3             -> 1 1
  pos 2 0               -> 5
  ```
- Separately: build `New("ab\ncde\n\nfg")`; for every `pos` in `[0, Len()]`
  assert `LineColToPos(PosToLineCol(pos)) == pos`.

- **Pin — `edit` bead, gap position after each op (verbatim, must be followed
  exactly, not re-derived):** `New(x)` leaves `GapPosition() == len(x)`.
  `Insert(pos, s)` leaves `GapPosition() == pos + len(s)` and requires
  `0 <= pos <= Len()` (`pos == Len()` is append). `Insert(pos, "")` just moves
  the gap to `pos`. `Delete(pos, n)` leaves `GapPosition() == pos`. Its guards
  run **in order**: `pos < 0 || n < 0` → `ErrArg` (checked first, without
  evaluating `pos + n`), then `pos + n > Len()` → `ErrRange`; so
  `Delete(-1, 100)` → `ErrArg`. From `New("hello world")`: `Insert(5,"XX")` → `"helloXX world"`,
  gap 7; then `Insert(0,">>")` → `">>helloXX world"`, gap 2; then
  `Delete(2,5)` → `">>XX world"`, gap 2.
- **Pin — `access` bead, bounds (verbatim):** `At` requires `0 <= pos < Len()`
  (`At(Len())` → `ErrRange`). `Slice` requires `0 <= start <= end <= Len()`
  (`Slice(0, Len())` is the whole text; `Slice(n, n)` is `""`; `end < start` →
  `ErrRange`). From `New("abcdef")`: `At(5)` → `'f'`; `At(6)` → `ErrRange`;
  `Slice(0,3)` → `"abc"`; `Slice(0,7)` → `ErrRange`.
- **Pin — `lines` bead, counting and bounds (verbatim, must be followed
  exactly):** `LineCount()` = `1 + count('\n')`; empty buffer → 1;
  `"a\n"` → 2. `LineBounds(line)` returns `[start, end)` **excluding** the
  trailing `\n`; last line's `end` is `Len()`. `PosToLineCol(pos)` accepts
  `pos == Len()`; a `pos` on a `\n` reports that line and `col` = the line's
  length. `PosToLineCol` and `LineColToPos` are exact inverses over
  `[0, Len()]`; `col` may equal the line length. From `New("line0\nline1\nline2")`:
  `LineBounds(1)` → `(6, 11)`; `PosToLineCol(5)` → `(0, 5)`;
  `PosToLineCol(6)` → `(1, 0)`; `PosToLineCol(17)` → `(2, 5)`;
  `LineColToPos(0, 6)` → `ErrRange`.
- **Pin — `gapbuffer` bead, grow correctness (verbatim):** after `grow`,
  `String()` and `Len()` are unchanged and `gapLen() >= need`. The after-gap
  text must be moved to the **end** of the new backing slice (not left directly
  after the before-gap text) — a random sequence of ~1000 `Insert`/`Delete` ops
  must keep `String()` byte-identical to an independently maintained `[]byte`.
- **Pin — `cli` / `integration` beads, output (verbatim):** for `insert`, split
  `<rest>` once on its first space — `<pos>` then the text argument kept
  byte-for-byte (leading/trailing spaces preserved), `unescape`d (`\n` `\t`
  `\\`); `insert 5` with no text → `Insert(5, "")` → `ok`. `text` / `at` /
  `slice` output is `escape`d to one line. `linebounds` prints `"<start>
  <end>"`, `linecol` prints `"<line> <col>"`. The only two `error: <e>` lines
  are `"error: gapbuffer: position out of range"` and `"error: gapbuffer: bad
  argument"`. A non-integer in any integer field → `"error: bad argument"`.
  Wrong field count → `"error: usage: <command> <signature>"`. Unknown command →
  `"error: unknown command <cmd>"`. Every error line begins with `"error: "`.
